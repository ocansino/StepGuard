StepGuard Phase 3 Manual Runbook
Purpose: GSM8K profile regression check and five-question StrategyQA smoke test

Run every command from:
B:\Thesis\StepGuard

IMPORTANT

- Commands labeled MODEL/API instantiate the configured OpenAI client and may make billable API requests. Run these yourself.
- Commands labeled LOCAL/OFFLINE do not instantiate model clients or perform NLI inference.
- The candidate-pool command performs model calls and NLI scoring. Treat it as MODEL/API.
- Stop at every checkpoint. Do not continue after a failed validator or a systematic manual-review problem.
- Do not paste API keys into commands, configuration files, logs, or this runbook.


Checkpoint 0 - Offline preflight

LOCAL/OFFLINE:

py -3.12 -B -m unittest discover -s tests -v

Expected result:

- All tests pass.


Checkpoint 1 - One-record GSM8K task-profile regression

MODEL/API - run manually:

py -3.12 -B -m src.cli generate-traces -c configs/gsm8k_openai_profile_regression.yaml

Expected artifact:

data/runs/gsm8k_openai_profile_regression_1/generated.jsonl

LOCAL/OFFLINE validator:

py -3.12 -B scripts/validate_phase3_artifacts.py --kind generated --artifact data/runs/gsm8k_openai_profile_regression_1/generated.jsonl --dataset data/raw/gsm8k_test_1.jsonl --expected-count 1 --task math

Manual check:

- The trace uses numbered Step N lines.
- The final answer is separate.
- The reasoning and final answer still look like the existing GSM8K behavior.
- No StrategyQA-specific yes/no instructions appear in the math output.

Stop if the validator fails or the math output format has changed unexpectedly.


Checkpoint 2 - Generate five frozen StrategyQA originals

MODEL/API - run manually:

py -3.12 -B -m src.cli generate-traces -c configs/strategyqa_openai_smoke_pool.yaml

Expected artifact:

data/runs/strategyqa_openai_smoke_shared/generated.jsonl

LOCAL/OFFLINE validator:

py -3.12 -B scripts/validate_phase3_artifacts.py --kind generated --artifact data/runs/strategyqa_openai_smoke_shared/generated.jsonl --dataset data/prepared/strategyqa_5.jsonl --expected-count 5 --task strategyqa

Manual check all five records:

- Correct qid, question, and gold answer.
- Numbered reasoning steps are present.
- The trace ends with exactly Final answer: yes or Final answer: no.
- model_answer is yes or no.
- The reasoning is concise and closed-book.
- There are no invented citations or claims of browsing/retrieved evidence.
- There is no math-specific wording or arithmetic-solution framing.

Stop if the validator fails or any domain/prompt problem appears systematically.


Checkpoint 3 - Build the shared calibrated candidate pool

MODEL/API - run manually:

py -3.12 -B -m src.cli build-candidate-pool -c configs/strategyqa_openai_smoke_pool.yaml

Expected artifact:

data/runs/strategyqa_openai_smoke_shared/candidate_pool.jsonl

LOCAL/OFFLINE validator:

py -3.12 -B scripts/validate_phase3_artifacts.py --kind candidate-pool --artifact data/runs/strategyqa_openai_smoke_shared/candidate_pool.jsonl --dataset data/prepared/strategyqa_5.jsonl --expected-count 5 --task strategyqa

Manual check:

- Every original score contains one verifier and contradiction value per parsed step.
- earliest_bad_step is either null or a valid zero-based step index.
- Every proposal contains parent_trace, parent_answer, candidate_trace, candidate_answer, candidate_score, and measured improvement.
- Every risk-improving proposal contains either a frozen judge result or an explicit judge error.
- Rejected or harmful candidates have not been discarded.
- Repaired suffix numbering begins at the localized risky step.
- The retained prefix was not modified.

Stop if the validator fails, score arrays are misaligned, or candidate artifacts are incomplete.


Checkpoint 4 - Apply four policies to the same pool

All four commands below are LOCAL/OFFLINE. They only read frozen scores, candidates, and judge results.

Risk-only:

py -3.12 -B -m src.cli apply-candidate-policy -c configs/strategyqa_openai_smoke_risk_only.yaml --input data/runs/strategyqa_openai_smoke_shared/candidate_pool.jsonl

Oracle:

py -3.12 -B -m src.cli apply-candidate-policy -c configs/strategyqa_openai_smoke_oracle.yaml --input data/runs/strategyqa_openai_smoke_shared/candidate_pool.jsonl

Strict judge:

py -3.12 -B -m src.cli apply-candidate-policy -c configs/strategyqa_openai_smoke_strict_judge.yaml --input data/runs/strategyqa_openai_smoke_shared/candidate_pool.jsonl

Updated judge:

py -3.12 -B -m src.cli apply-candidate-policy -c configs/strategyqa_openai_smoke_updated_judge.yaml --input data/runs/strategyqa_openai_smoke_shared/candidate_pool.jsonl

Validate each output locally:

py -3.12 -B scripts/validate_phase3_artifacts.py --kind policy-output --artifact data/runs/strategyqa_openai_smoke_risk_only/iterative_repaired.jsonl --dataset data/prepared/strategyqa_5.jsonl --expected-count 5 --task strategyqa

py -3.12 -B scripts/validate_phase3_artifacts.py --kind policy-output --artifact data/runs/strategyqa_openai_smoke_oracle/iterative_repaired.jsonl --dataset data/prepared/strategyqa_5.jsonl --expected-count 5 --task strategyqa

py -3.12 -B scripts/validate_phase3_artifacts.py --kind policy-output --artifact data/runs/strategyqa_openai_smoke_strict_judge/iterative_repaired.jsonl --dataset data/prepared/strategyqa_5.jsonl --expected-count 5 --task strategyqa

py -3.12 -B scripts/validate_phase3_artifacts.py --kind policy-output --artifact data/runs/strategyqa_openai_smoke_updated_judge/iterative_repaired.jsonl --dataset data/prepared/strategyqa_5.jsonl --expected-count 5 --task strategyqa

Expected result:

- Every validator reports PASS.
- All four outputs reference the frozen candidate pool.
- Their candidate traces are identical where they evaluate the same parent state.
- Strict judge may reject a candidate that updated judge accepts when prefer_repaired is false but support and regression checks pass.

Final Phase 3 go/no-go review

Proceed to the 100-question experiment only if:

- The math regression output is structurally normal.
- All five StrategyQA generations pass manual review.
- All score arrays align with parsed steps.
- Candidate traces and judge results are complete.
- No math-specific prompt behavior appears in StrategyQA.
- No correct/gold labels or dataset records changed.
- Risk-only, oracle, strict, and updated policy decisions are internally consistent.
- Every accepted and rejected candidate remains available for inspection.

If a command fails, preserve its output and error message. Do not rerun model-backed commands automatically before identifying whether the existing artifact can be reused.
