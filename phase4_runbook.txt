StepGuard Phase 4 Manual Runbook
Purpose: 100-question StrategyQA experiment and Table 3 equivalent

Run every command from:
B:\Thesis\StepGuard

IMPORTANT

- Commands labeled MODEL/API instantiate the configured OpenAI client and may make billable API requests. Run these yourself.
- Commands labeled LOCAL/OFFLINE do not instantiate model clients or perform NLI inference.
- Candidate-pool construction performs model calls and NLI scoring. Treat it as MODEL/API.
- Stop at each checkpoint and validate the saved artifact before making additional model calls.
- Do not rerun a failed model-backed command until checking whether it left a complete reusable artifact.
- Do not paste API keys into commands, configs, logs, or this runbook.


Experiment layout

- Generate the 100 original traces exactly once under strategyqa_openai_100_calibrated_shared.
- Build the calibrated candidate pool once and reuse it for calibrated risk-only, oracle, strict judge, and updated judge.
- Build a separate aggressive candidate pool because its additive risk formula and 0.10 threshold can localize different steps.
- The aggressive pool reuses the calibrated pool's frozen original verifier and NLI scores, then recomputes risk using the aggressive formula. It does not rescore the 100 original traces.
- Apply every acceptance policy offline to its frozen pool.

Checkpoint B2 - Build the separate aggressive candidate pool

MODEL/API - run manually:

Expected artifact:

The --reuse-original-scores option preserves the calibrated pool's original verifier and NLI outputs while recomputing risk with the additive formula and 0.10 threshold. Repair candidates identified by the aggressive trigger are still generated and scored under the aggressive configuration.

LOCAL/OFFLINE validator:

py -3.12 -B scripts/validate_phase3_artifacts.py --kind candidate-pool --artifact data/runs/strategyqa_openai_100_aggressive_shared/candidate_pool.jsonl --dataset data/prepared/strategyqa_100.jsonl --expected-count 100 --task strategyqa

Stop if this validator fails. Do not apply policies until both pools contain 100 valid records.

- Every policy decision refers to a candidate from the correct frozen pool.
- Accuracy transitions and proposal classifications are calculated from saved records.

Checkpoint C3 - Manual scientific review

Review proposal_analysis.jsonl and select, when available:

- One safe accepted repair.
- One harmful candidate blocked by a guard.
- One harmful candidate accepted by risk-only.
- One beneficial wrong-to-correct candidate.
- One false-positive intervention on an originally correct trace.
- Any final correct-to-wrong or wrong-to-correct transition shown in the table.

For every selected example, confirm that the automated classification matches the question, gold answer, parent answer, candidate answer, and policy decision.


Final go/no-go rule

The StrategyQA table is ready for the advisor only if:

- Every validator reports PASS.
- Judge errors are absent or individually understood and reported.
- Original traces and original accuracy are identical across all five configurations.
- Configurations 2-5 use one calibrated candidate pool.
- The aggressive setting differs only in its risk formula, threshold, and resulting trigger/candidate path.
- Every table count is reproduced from saved artifacts.
- Qualitative labels have been manually checked.
- The paper describes this as a closed-book 100-example public-training-subset transfer study without threshold retuning.
